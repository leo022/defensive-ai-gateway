# Response Agent 深度调查报告样例

样例 Case：`case_rasp_VM-0-7-centos_cloudrasp_list_file_102`

说明：本样例根据 2026-07-27 至 2026-07-28 已入库的 4 条 RASP 原始告警编写，用于定义 v7 报告应达到的分析深度和证据边界。它不是对历史会话的回写，也不代表已经完成实时主机、EDR、WAF 或网络设备取证。

## 1. 执行摘要

源 IP `43.154.138.159` 在约 21 小时内持续访问同一目标 `106.53.107.29:8080`、同一主机 `VM-0-7-centos` 和应用 `ai_agent`。RASP 先后观察到 `/etc/passwd` 文件读取、远程 UNC 库路径加载和 OGNL 表达式触发目录枚举，涉及 4 条高危或严重告警。事件在来源、目标、应用和时间上形成连续活动，行为跨越文件发现、敏感文件访问和潜在代码/库加载，符合有目的的多技术利用活动，而不是彼此孤立的误报。

现有证据可以高置信确认恶意利用活动到达 RASP 插桩的应用运行时，但不能确认攻击者已取得持久控制或成功获取 HTTP 响应内容。四条记录的 RASP 动作为 `log`，不等于阻断；`response_message.status_code=0` 不是合法 HTTP 状态，因此请求最终是否成功返回数据仍未知。

## 2. 风险判断

| 维度 | 判断 |
|---|---|
| 风险等级 | 严重 |
| 攻击状态 | 已确认恶意活动；主机失陷未确认 |
| 可能性 | 高 |
| 潜在影响 | 高 |
| 主要加重因素 | 同源同目标重复活动；多种利用技术；危险操作到达运行时；涉及 `/etc/passwd` 与远程库路径 |
| 主要缓解因素 | 尚无独立 EDR/HIPS/主机证据证明命令执行、持久化或横向移动；HTTP 返回结果未知 |

结论分类：`malicious_activity_confirmed`。不得提升为“主机已确认失陷”，除非补充进程、文件、网络、认证或持久化证据。

## 4. 关联活动分析

四条事件共享源 IP `43.154.138.159`、目标 `106.53.107.29:8080`、主机 `VM-0-7-centos` 和应用 `ai_agent`，且全部为 RASP 高危或严重运行时检测。关联关系由 Case 实体和原始告警字段共同建立，而不是仅靠相同规则名。

活动序列表明攻击者先验证敏感文件读取，再探测远程库加载，最后触发 OGNL 表达式目录枚举。该顺序支持“持续试探同一易受攻击应用的不同攻击面”假设。由于当前受治理数据库中没有独立 WAF、EDR、HIPS、NDR 或主机审计事件，不能据此确认后续命令执行、持久化、外连或数据外泄；这些来源未覆盖不是负面证据。

## 5. 关键发现

1. `confirmed`：同一来源在约 21 小时内对同一应用发起至少 4 次关联的高风险活动，引用四条 RASP 原始告警。
2. `confirmed`：RASP 插桩运行时观察到 `/etc/passwd` 文件读取调用、OGNL 目录枚举表达式和远程 UNC 库路径参数。
3. `confirmed`：两条文件读取事件的请求载荷分别属于 GET 无查询串和 POST `Content-Length: 0` 的明确空载荷；先前“正文未采集或被 prompt 截断”的说法不成立。
4. `confirmed`：四条记录均未保存可验证的 HTTP 响应状态；值 `0` 不能解释为成功、失败或阻断。
5. `inferred`：多技术、重复、同源同目标的模式更符合协调的恶意利用活动，而非单次误触发。
6. `unverified`：远程库是否成功加载、文件内容是否返回、是否产生子进程、是否建立持久化、是否横向移动或外泄数据。

## 6. 攻击链判断

1. 初始访问：攻击者能够从外部到达应用的多个测试/表达式端点。
2. 发现与敏感文件访问：两次触发 `/etc/passwd` 读取路径，随后枚举 `/usr` 目录。
3. 执行能力探测：向 JNI 加载路径提供远程 UNC 库地址，具有潜在代码加载风险。
4. 失陷后活动：当前没有足够证据确认进程执行、权限提升、凭据访问、持久化、横向移动或数据外泄。

前三项由具体 RASP 事件支撑；“执行能力探测”不等同于已执行成功。

## 7. 影响与范围

当前确认范围限定为 `VM-0-7-centos` 上的 `ai_agent` 应用和 `106.53.107.29:8080` 暴露面。潜在影响包括敏感本地文件读取、目录结构泄露以及远程库加载导致的代码执行。实际数据返回、主机文件变化、子进程、异常连接和凭据影响尚未验证，因此不能扩大为全主机或横向环境失陷结论。

## 8. 响应计划

| 优先级 | 动作 | 模式 |
|---|---|---|
| P0 | 在负载均衡、WAF、反向代理和 Web 访问日志中补采四个时间点前后请求与响应，按源、目标、URI、request ID 关联 | `observe` |
| P0 | 通过 EDR/HIPS/Sysmon/auditd 只读查询补采对应时间窗的 Java/Tomcat 进程树、命令行、模块加载、文件访问和外连 | `observe` |
| P0 | 保全应用日志、容器日志、Webroot、上传/临时目录及相关文件元数据和哈希 | `observe` |
| P0 | 临时隔离受影响主机或封禁源 IP，仅在分析员确认业务影响和范围后执行 | `approve_required` |
| P1 | 检查服务、计划任务、启动项、Shell 配置、动态加载项和账号/权限变更 | `observe` |
| P1 | 轮换可能受影响的应用凭据、重部署干净实例或删除可疑文件 | `approve_required` |

任何隔离、终止进程、删除文件、封禁、凭据轮换和重部署都不能以 `observe` 模式自动执行。

## 9. 精确证据限制

1. 四条 RASP 记录的 HTTP 响应状态均为 `0`，无法验证 HTTP 成功、失败、返回内容或实际阻断。
2. 当前查询范围内只有 RASP 受治理遥测，没有独立 WAF、EDR、HIPS、NDR、DNS、防火墙或主机审计证据。
3. RASP `action=log` 只描述记录动作，不能证明攻击被拦截。
4. 原始 Syslog 已由 Agent 从 offset 0 连续读取到结束，可以证明数据库内脱敏后选定对象读取完整；这不证明发送端采集了所有字段，也不证明源端到采集器的传输完整性。
5. 关联扫描受时间窗、候选笔数和原始位元组预算约束，不应表述为全环境无限范围检索。

## 10. 最终结论

这是一起高置信、持续且跨多种技术的恶意应用利用活动。现有 RASP 证据足以要求立即补充 Web、主机、端点和网络取证，并准备受审批的遏制动作；但不足以宣称攻击已被阻断，也不足以确认主机持久失陷、横向移动或数据外泄。后续决策应以只读保全和补采为先，获得独立主机或端点证据后再升级失陷等级并执行隔离、清除或凭据轮换。
